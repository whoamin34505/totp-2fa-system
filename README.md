# TOTP 2FA System

Система двухфакторной аутентификации на основе алгоритма TOTP (Time-Based One-Time Password).

Проект включает серверную часть на Python/FastAPI, базу данных PostgreSQL, веб-интерфейс и iOS-приложение-аутентификатор на SwiftUI.

## Возможности

- Регистрация и авторизация пользователей по паролю.
- Подключение двухфакторной аутентификации через QR-код.
- Генерация и проверка одноразовых TOTP-кодов.
- Шифрование TOTP-секретов с использованием AES-256-GCM.
- Защита от повторного использования одноразовых кодов.
- Ограничение количества ошибочных попыток ввода TOTP.
- Управление пользовательскими сессиями.
- Хранение данных в PostgreSQL.
- Развёртывание серверной части через Docker Compose.

## 1. Требования

Для запуска сервера необходимы:

- Docker с поддержкой Docker Compose.
- Свободный локальный порт 8000.
- Git — для получения исходного кода.
- Python 3 — для приведённой ниже команды генерации ключа.

PostgreSQL и зависимости сервера отдельно устанавливать не требуется: они находятся в контейнерах.

## 2. Подготовка

Склонируйте репозиторий проекта и перейдите в директорию серверной части:

```bash
git clone https://github.com/whoamin34505/totp-2fa-system.git
cd totp-2fa-system/server
```

Создайте файл конфигурации:

```bash
cp .env.example .env
chmod 600 .env
```

Для новой установки сгенерируйте ключ AES-256 в формате Base64:

```bash
python3 -c 'import secrets, base64; print(base64.b64encode(secrets.token_bytes(32)).decode())'
```

Скопируйте полученную строку в `TOTP_AES_KEY` файла `.env`. Команда использует стандартную библиотеку Python и не требует установки зависимостей приложения.

Заполните переменные в `.env`:

| Переменная | Назначение |
|---|---|
| `TOTP_AES_KEY` | Ключ шифрования TOTP-секретов |
| `TOTP_ISSUER` | Название сервиса для приложения-аутентификатора |
| `APP_ORIGIN` | Публичный адрес веб-приложения |
| `SESSION_COOKIE_SECURE` | Передача сессионных cookie только через HTTPS |
| `DB_NAME` | Имя базы данных |
| `DB_USER` | Пользователь PostgreSQL |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `DB_HOST` | Адрес контейнера PostgreSQL |

Пример настроек для локального запуска:

```env
TOTP_AES_KEY=<сгенерированный_Base64_ключ>
TOTP_ISSUER=totp-2fa-system
APP_ORIGIN=http://127.0.0.1:8000
SESSION_COOKIE_SECURE=false

DB_NAME=totp_2fa_system
DB_USER=postgres
DB_PASSWORD=<пароль>
DB_HOST=db
```

`TOTP_AES_KEY` должен содержать 32 случайных байта, закодированных в Base64. `APP_ORIGIN` должен точно совпадать с адресом сайта в браузере, включая схему и порт: например, `localhost` и `127.0.0.1` считаются разными адресами.

**Важно:** не публикуйте `.env` в Git. Не заменяйте ключ на работающей установке: потеря или замена ключа сделает невозможной расшифровку ранее сохранённых TOTP-секретов.

## 3. Запуск Docker Compose

В директории `server` выполните:

```bash
docker compose up -d --build
```

Docker Compose автоматически:

1. Соберёт образ FastAPI.
2. Создаст контейнер PostgreSQL.
3. Создаст базу данных и таблицы при первой инициализации.
4. Запустит сервер FastAPI.

Проверьте состояние контейнеров:

```bash
docker compose ps
```

Откройте веб-интерфейс:

http://127.0.0.1:8000

Проверка API:

```bash
curl http://127.0.0.1:8000/status
```

Ожидаемый ответ:

```json
{
  "application": "totp-2fa-system",
  "status": "running"
}
```

Этот ответ подтверждает, что веб-сервер запущен; доступность базы данных он не проверяет.

## 4. Управление контейнерами

| Действие | Команда |
|---|---|
| Запуск | `docker compose up -d` |
| Сборка и запуск | `docker compose up -d --build` |
| Проверка состояния | `docker compose ps` |
| Просмотр логов | `docker compose logs -f` |
| Перезапуск | `docker compose restart` |
| Остановка и удаление контейнеров | `docker compose down` |

Данные PostgreSQL хранятся в отдельном Docker volume и сохраняются при обычной остановке или пересоздании контейнеров.

## 5. Развёртывание на VPS

Для публичного размещения рекомендуется использовать обратный прокси Nginx с HTTPS.

Пример архитектуры:

```text
Интернет
    |
    v
Nginx (HTTPS)
    |
    v
127.0.0.1:8000
    |
    v
Docker: FastAPI
    |
    v
Docker: PostgreSQL
```

В `compose.yaml` сервер FastAPI должен быть опубликован только на локальном интерфейсе:

```yaml
ports:
  - "127.0.0.1:8000:8000"
```

Для HTTPS в `.env` установите:

```env
APP_ORIGIN=https://your-domain.example
SESSION_COOKIE_SECURE=true
```

После изменения `.env` примените настройки из директории `server`:

```bash
docker compose up -d
```

Пример блока обратного проксирования Nginx внутри HTTPS-сервера:

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
}
```

HTTPS-сертификат и соответствующий серверный блок Nginx должны быть настроены отдельно.

После изменения конфигурации Nginx проверьте её:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Если порт 443 занят другим приложением, например Xray, необходимо согласовать маршрутизацию HTTPS-трафика с уже существующей инфраструктурой.

## 6. Подключение к PostgreSQL

Для подключения к PostgreSQL через терминал контейнера:

```bash
docker compose exec db psql -U postgres -d totp_2fa_system
```

Команда выше использует значения из примера. Если в `.env` указаны другие `DB_USER` и `DB_NAME`, используйте их вместо `postgres` и `totp_2fa_system`.

Просмотр таблиц:

```sql
\dt
```

Просмотр пользователей:

```sql
SELECT id, username, two_factor_enabled
FROM users;
```

База данных не публикуется в интернет.

## 7. Обновление приложения

После получения новой версии исходного кода выполните:

```bash
docker compose up -d --build
```

При пересборке сохраняются существующие Docker volumes и файл `.env`.

Изменения структуры базы данных, если они появились в новой версии, должны применяться отдельно. Скрипты инициализации PostgreSQL выполняются автоматически только при создании нового хранилища данных.

## 8. Проверка работоспособности

После установки рекомендуется проверить полный сценарий аутентификации:

1. Зарегистрировать тестового пользователя.
2. Войти с логином и паролем.
3. Подключить TOTP через QR-код.
4. Подтвердить подключение одноразовым кодом.
5. Выйти из аккаунта, дождаться нового кода и авторизоваться повторно. Код, использованный при подтверждении подключения, повторно не принимается.
6. Проверить отклонение неправильного и повторно использованного TOTP-кода.

## 9. Безопасность

В проекте используются шифрование секретов AES-256-GCM, хеширование паролей, одноразовые коды TOTP и механизм пользовательских сессий.

Для публичного развёртывания необходимо использовать HTTPS, защищать конфигурационные файлы и регулярно создавать резервные копии PostgreSQL и AES-ключа.

Ограничение попыток ввода TOTP не заменяет отдельную защиту от перебора обычных паролей.

## 10. iOS-приложение

Приложение OTPAuth сканирует QR-код подключения, хранит секрет в Keychain и генерирует коды на устройстве. Для сборки нужны Mac с Xcode и iPhone; требуется минимальная версия iOS 26.6.

1. Откройте `ios/TOTPAuthenticator/TOTPAuthenticator.xcodeproj` в Xcode.
2. Выберите цель `TOTPAuthenticator` и в **Signing & Capabilities** укажите свою команду разработчика. При необходимости измените Bundle Identifier.
3. Выберите подключённый iPhone и запустите приложение кнопкой **Run**.
4. На сайте включите 2FA, отсканируйте показанный QR-код приложением и введите полученный код для подтверждения.

Для сканирования QR-кода с экрана компьютера iPhone не требуется подключаться к серверу по сети.
